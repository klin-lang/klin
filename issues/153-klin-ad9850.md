## Why separate (same reasoning as G-149)

The AD9850 is a bus-agnostic chip: some modules are serial (`D7`/`W_CLK`/`FQ_UD`),
some parallel. Like [`klin_xpt2046`](https://github.com/klin-lang/klin_xpt2046),
the driver stays MCU-agnostic (`Wire` / `ctx`) and the app owns the pins, so it
never pulls a HAL or a specific board into unrelated apps.

## Scope (`@v0.1.0`)

- `tuning_word` / `freq_from_word` — integer FTW ↔ Hz (no float)
- `control_byte` / `word_byte` — W4 byte and LSB-first byte extraction
- `Wire` — `write` (byte, LSB first) + `latch` (FQ_UD) + `reset` + `ctx`
- `attach(wire, ref_hz)` — no heap; stores wire + reference clock
- `send` / `set_freq` / `set_freq_phase` / `power_down` / `reset`
- `default_ref_hz()` → `125000000`
- Host `klin test` + `examples/host_smoke.kl`

### Later (not this tag)

- Parallel-load mode (`D0..D7` + `W_CLK`/`FQ_UD`)
- Sweep / ramp helpers
- Phase in degrees (today it is the raw 5-bit code)

## Out of scope

- Board packs, HAL, or a specific `machine_*` dependency
- Hidden allocation, DMA, or float

## Contract (prime rule)

- No Klin GC / hidden heap; the emitted C is the arithmetic you would write by hand.
- Serial load: 40 bits LSB-first (four FTW bytes then the W4 control byte), latched by `FQ_UD`.
- Data path is `i64` because the MVP has no integer-width cast and FTW needs a 64-bit intermediate.
