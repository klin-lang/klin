## Why separate (not one “TFT board” lib)

A common 1.8″ ST7735S module (e.g. [msalamon TFT-00008](https://sklep.msalamon.pl/produkt/wyswietlacz-dotykowy-tft-lcd-1-8″-128x160px-rgb-spi-st7735s/)) can expose:

| Device | Chip | Package |
|---|---|---|
| LCD | ST7735S | [`klin_st7735`](https://github.com/klin-lang/klin_st7735) |
| Touch | XPT2046 | **this** (`klin_xpt2046`) |
| microSD | SPI card | [150](150-sd-spi-fatfs.md) later |

One mega-lib would couple unrelated protocols and pull FatFs cost into every LCD-only app. Chip drivers stay MCU-agnostic (`Wire` / `ctx`); the app owns the bus.

Black Pill F411 ([msalamon](https://sklep.msalamon.pl/produkt/stm32f411ceu6-dev-board/)) lists **SDIO** as an on-chip peripheral — **not** an onboard SD slot. Do not fold SD into `weact-f411` ([147](147-board-weact-f411.md)).

## Scope (`@v0.1.0`)

- `Wire` — `xfer(ctx, cmd) → i32` (CS low, 8-bit command, 16-bit MISO, CS high) + `ctx`
- `attach(wire)` — no heap; no hidden init beyond storing the wire
- `raw()` / `read(z_thresh)` / `pressed(z_thresh)` — 12-bit X/Y/Z
- `adc12` / `map` — raw → 12-bit; linear map for app-side calibration
- `default_z_thresh()` → `400`
- Host `klin test` + `examples/host_smoke.kl`
- Example: `examples/msalamon_tft18_blackpill/` (LCD + touch; `SD_CS` idle HIGH)

### Later (not this tag)

- IRQ pin helpers / interrupt edge in the driver (app can poll a `Pin` today)
- Averaging / filtering beyond one sample block
- Multitouch (XPT2046 is single-touch)

## Out of scope

- Folding into `klin_st7735`, `machine_stm32`, or `weact-f411`
- SD / FatFs / SDIO ([150](150-sd-spi-fatfs.md))
- Hidden allocation, DMA, or framebuffer

## Contract (prime rule)

- No Klin GC / hidden heap.
- SPI Mode 0, MSB first; baud is caller-owned (typically ≤ 2 MHz for touch).
- Calibration (raw ADC → panel pixels) stays in the app (`map`).
